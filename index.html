NYC FloodGuard — IoT System Architecture & Hardware Blueprint

How ultrasonic edge sensors on an Arduino GIGA R1 WiFi connect to a cloud database and this human-centered web interface.

Layer 1 • Edge Sensing Node

Arduino GIGA R1 WiFi + Ultrasonic Transducer

Weatherproof ultrasonic sensors (JSN-SR04T / HC-SR04) are mounted on street light poles or bridge underpasses at a calibrated height H_mount above the street surface.

The dual-core STM32H747XI processor emits a 40 kHz acoustic pulse, measures the time-of-flight echo t_echo, applies temperature compensation, and transmits JSON payloads over onboard Murata Wi-Fi every 5 seconds.

Layer 2 • API & Time-Series Database

Low-Latency Ingestion & Persistence

In production deployment, sensor nodes authenticate via TLS to a REST/WebSocket ingestion endpoint backed by PostgreSQL / TimescaleDB for shared multi-user persistence.

In this prototype, script.js encapsulates all data calls inside a modular FloodGuardAPI class that uses browser localStorage as a local drop-in store until the backend URL is enabled.

Layer 3 • Human-Centered Web UI

Resilient, Role-Adaptive Frontend

Displays new readings within 5 seconds of receipt, automatically highlights outdated sensor data (>15s old), and survives temporary internet drops without crashing.

Uses a high-contrast Navy, White, Cyan, and Slate Gray palette while reserving Orange and Red strictly for flood warnings.
